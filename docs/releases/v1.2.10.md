# v1.2.10 — Disk-first retention

Fixes the quota error that prevented automatic cleanup in v1.2.9. The renderer keeps a pending request in memory while the native helper writes its 1,000-record backup directly to disk. Only acknowledgment of that exact backup allows the renderer to save the smaller active list. Failure, reload, or intervening edits never authorize an unbacked deletion.

Active documents and backups now transfer in bounded chunks instead of one large WebSocket response. Unicode surrogate pairs are preserved. Legacy pending page-storage backups are archived and cleared without pruning twice.

The helper still never restarts Codex in the background. Retention may take one normal monitoring cycle (about 15 seconds); keep the window open until the completion notice appears.
