# Codex Highlighter v1.2.9

New selections no longer stop working at 2,000 saved highlights. On reaching that threshold, the oldest 1,000 by creation time are backed up and removed from the active list. An existing full store cleans up on the next new highlight and retains the newest 1,000 plus the new selection.

Recoloring, loading, importing and manually deleting highlights do not invoke retention. The removed batch is saved before the active list changes. A pending batch cannot be overwritten, and the native host acknowledges it only after storing it under `%LOCALAPPDATA%\CodexHighlighter\backups\auto-prune`. Backup files remain available and are excluded from normal highlighting scans.

Verified with 1,998/1,999/2,000 record fixtures, reversed age order, renderer reload, storage failures, unacknowledged backups, disk retries, conflicting backup IDs, and recoloring at capacity. Codex's no-background-restart behavior is unchanged.
